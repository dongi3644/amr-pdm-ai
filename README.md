# AMR 구동부 고장 예지 AI (third_model)

배송 로봇(AMR) 바퀴 구동부에 싼 센서(MPU6050 진동 · INA219 전류 · 바퀴 엔코더)를 달고, **고장이 났는지 · 어느 바퀴의 무슨 고장인지**를 1분마다 알려 주는 AI입니다.
2026 DSC 공유대학 × KT AI 활용 지역문제 해결 캠프 참가작.

**코드와 설명은 모두 [`third_model/`](third_model/README.md)에 있습니다.**

| [third_model/최종_성능과_시험_조건.md](third_model/최종_성능과_시험_조건.md) | **최종 성능표와 그 성능이 나온 시험 조건만 따로 정리** |
| [third_model/코드_파일_설명.md](third_model/코드_파일_설명.md) | 코드 파일마다 하는 일 |

```
센서 기록 → 1초씩 자르기 (로봇마다 처음 5분 = 평소)
 → 특징 121개 (진동 · 바퀴 · 엔코더 1회전 속도 모양 · 주파수 모양 · 1회전 박자)
 ├→ 주파수 모양 오토인코더 (비지도 딥러닝) → 처음 보는 고장
 ├→ 랜덤포레스트 (지도) → 아는 고장 + 원인 · 근거
 └→ 바퀴 점수 (규칙)
      → 1분마다 정상 · 주의 · 경고, 원인 (종류 · 바퀴 또는 '처음 보는 이상')
 전류 · 전압 → 규칙 감시 (전류 높음 · 배터리 낮음 · 사용량)
```

## 최종 성능 (가상 로봇 시험, 실측 성능 아님)

| 지표 | 결과 | 대수 | 뜻 |
|---|---|---|---|
| ① 전체 정답률 | **97.6%** | 166대 중 162대 | 고장 로봇은 고장으로, 정상 로봇은 정상으로 맞게 판정 |
| ② 아는 고장 찾기 | **96.3%** | 54대 중 52대 | 학습한 고장 (바퀴 불균형 · 체결 풀림 · 마찰 증가) |
| ③ 처음 보는 고장 찾기 | **94.9%** | 39대 중 37대 | 학습에 없던 고장 (기어 마모 · 바퀴 찍힘 · 새 주파수 베어링) → '처음 보는 이상'으로 알림 |
| ④ 고장 원인 맞히기 | **96.6%** | 찾은 89대 중 86대 | 종류(아는 고장) 또는 '처음 보는 이상'(처음 보는 고장)이 맞음 |
| ⑤ 잘못 울린 경보 | **0.0%** | 정상 73대 중 0대 | 멀쩡한 로봇인데 고장이라고 한 비율 (낮을수록 좋음) |

- 놓친 고장 4대는 모두 약한 고장: 바퀴 찍힘 2대(세기 0.46 · 0.50배), 마찰 증가 1대(0.52배), 바퀴 불균형 1대(0.68배)
- 원인을 틀린 3대: 체결 풀림 1대 · 바퀴 찍힘 2대를 '바퀴 불균형'으로 봄 (고장이라는 것은 맞게 알림)
- 성능표와 시험 조건만 따로: [third_model/최종_성능과_시험_조건.md](third_model/최종_성능과_시험_조건.md) · 이전 결과까지는 [third_model/README.md 5절](third_model/README.md)

## 빠른 시작
1. 코드 받기: `git clone https://github.com/dongi3644/amr-pdm-ai.git` (또는 `Code` → `Download ZIP`)
2. VS Code로 **`third_model` 폴더**를 열고 `실행 및 디버그` → `1. 환경 설치` (Python 3.9 이상)
3. 팀 실측 폴더 4개를 `third_model/data/` 아래에 넣고 `2. 가상 성능 시험` 실행 (약 15분) → 위 성능표가 터미널에 나오고 `가상테스트_결과/성능시험/`에 `결과_요약.txt` · `결과_그림.png`로 저장
4. 실험 없이 지난 결과만 보려면 `3. 지난 결과 다시 보기`

실측 데이터 · 학습 결과 · 아두이노 스케치는 GitHub에 올리지 않습니다.

## 가상 데이터를 만드는 파일

가상 로봇은 팀 실측 데이터를 재료로 `third_model/가상테스트/`에서 만들어집니다 (자세한 방법은 [third_model/README.md 4절](third_model/README.md)).

| 파일 | 하는 일 |
|---|---|
| [가상테스트/실측보정_로봇.py](third_model/가상테스트/실측보정_로봇.py) | **가상 로봇을 실제로 만드는 곳.** 실측 정상 진동 · 전류 · 전압을 2~6초 조각으로 잘라 이어 붙이고, 그 위에 고장 진동을 얹고, 엔코더 4개를 만듦 |
| [가상테스트/sim_robots.py](third_model/가상테스트/sim_robots.py) | **로봇 조건 정하기.** 고장 종류 · 바퀴 · 시작 시각 · 진행 · 간헐 · 복합 고장, 바닥 바뀜 · 짐 실음 같은 헷갈리는 정상 |
| [가상테스트/성능시험.py](third_model/가상테스트/성능시험.py) | 위 두 파일로 학습 · 검증 · 시험 로봇을 한꺼번에 만들어 학습하고 채점 (VS Code `2. 가상 성능 시험`) |
| [가상테스트/가상로봇_저장.py](third_model/가상테스트/가상로봇_저장.py) | 가상 로봇 몇 대만 골라 **CSV로 저장** (열어 보기용, VS Code `가상 로봇 몇 대 CSV로 저장`) |
| [pipeline/augment.py](third_model/pipeline/augment.py) | 학습 때만 쓰는 **가상 이상** (정상 기록 복사본에 무작위 떨림 · 순음 · 충격을 넣어 '처음 보는 이상'으로 가르침) |

`실측보정_로봇.py` 안에서 볼 곳
- `RealPools`: `data/`의 실측 CSV를 읽어 바닥 · 속도별 조각으로 묶고, 파일 단위로 학습 · 검증 · 시험으로 나눔
- `FaultModel`: 테이프 고장 기록에서 '고장 − 정상' 진동 증가분을 계산 (불균형 고장에 씀)
- `make_table`: 로봇 1대를 만드는 함수. 고장마다 진동을 넣는 부분(`unbalance` · `looseness` · `bearing` · `gear` · `flat`)과 엔코더를 만드는 부분

가상 로봇을 직접 열어 보려면 (`third_model` 폴더에서, 정상 1대 + 고장 5종류 → `가상테스트_결과/가상로봇_CSV/`):
```
.venv/Scripts/python.exe 가상테스트/가상로봇_저장.py --normal 1 --fault unbalance,looseness,bearing,gear,flat
```

## 이 성능이 나온 조건

**한 줄로:** 팀이 기록한 실측 데이터로 만든 '가상 로봇'으로 학습하고, AI가 한 번도 못 본 가상 로봇 166대로 시험한 결과입니다. 실제 로봇의 성능은 실측 고장 기록으로 다시 확인해야 합니다.

| 항목 | 조건 |
|---|---|
| 실행 명령 | `python 가상테스트/성능시험.py` (기본값 그대로 = VS Code `2. 가상 성능 시험`). 기본값: `--seed 2031 --val-scale 1.0 --test-scale 2.0 --cond 0.5-1.0 --test-shift 1` |
| 쓴 데이터 | 팀 실측 4폴더 (공3옥상 정상 2 · 욧골 정상 1 · 욧골 테이프 고장 1). 실측 파일을 **학습 40 · 검증 14 · 시험 19개**로 나눠, 시험 로봇은 학습에 안 쓴 파일로만 만듦 |
| 가상 로봇 | 실측 정상 진동 · 전류 · 전압의 2~6초 조각을 이어 붙이고 고장 진동을 얹음. 불균형은 실측 테이프 고장에서 잰 '고장 − 정상' 차이, 나머지 고장 모양은 가정(세기만 실측에 맞춤). 엔코더 4개는 바퀴 회전 식으로 만듦(실측 엔코더는 1개뿐) |
| 학습 | 가상 로봇 44대(고장 27대) + 정상 기록에 무작위 이상을 넣은 복사본 11대 |
| 설정 고르기 | 검증 로봇 83대(아는 고장만)로 고름 → 주의 2.0점 · 경고 6점 · 2번 연속 · 간헐 0.65 · '원인 미확정' 0.3. **시험 로봇은 보지 않음** |
| 시험 로봇 | 166대 = 고장 93대(그중 **39대는 학습에 없던 고장**) + 정상 73대. 헷갈리는 정상(바닥 바뀜 · 짐 실음 · 저전압 · 속도 바뀜) 포함 |
| 고장 세기 | 로봇마다 0.5~1.0배 무작위 (1.0 = 기본 세기, 약할수록 찾기 어려움) |
| AI | 주파수 모양 오토인코더(비지도) + 랜덤포레스트(지도) 2개, 보조로 바퀴 점수(규칙) |
| 맞음의 기준 | 고장: 고장 시작 뒤에 주의 이상으로 알리면 찾음. 정상: 기록 내내 한 번도 경보가 없어야 맞음 |
| 다시 해 보기 | 같은 명령을 다시 돌리면 같은 로봇 · 같은 모델이라 같은 숫자가 나옴 (11/20 노트북에서 처음부터 다시 돌려 확인. 패키지 버전이 다르면 조금 달라질 수 있음) |
