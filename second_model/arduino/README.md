# 아두이노 기록기 (MPU6050 + INA219)

`amr_logger/amr_logger.ino`를 아두이노에 올리면, 진동(MPU6050)과 전류·배터리 전압(INA219)을 읽어 USB 시리얼로 보냅니다. PC에서 `실행/0_아두이노_기록.py`를 실행하면 그 값을 받아 `data/` 폴더에 CSV로 저장합니다.

## 연결 (아두이노 우노 기준)

두 모듈을 같은 I2C 선(SDA, SCL)에 나란히 연결합니다.

| 모듈 | VCC | GND | SDA | SCL | 그 밖 |
|---|---|---|---|---|---|
| MPU6050 | 5V | GND | A4 | A5 | AD0는 연결하지 않음 (주소 0x68) |
| INA219 | 5V | GND | A4 | A5 | **VIN+ ← 배터리 +**, **VIN- → 모터 드라이버 전원 +** |

```
배터리 + ──→ [INA219 VIN+ ─ 션트 저항 ─ VIN-] ──→ 모터 드라이버(L298N/TB6612) 전원 +
배터리 - ──────────────────────────────────────→ 모터 드라이버 GND ── 아두이노 GND
```

- 배터리 -와 아두이노 GND가 이어져 있어야 전압이 바르게 읽힙니다.
- INA219 모듈의 션트 저항은 보통 0.1 Ω(`R100`)이고, 이때 ±3.2 A까지 잴 수 있습니다. 저항 값이 다르면 `pipeline/arduino.py`의 `SHUNT_OHM`을 바꾸세요.
- MPU6050은 차체에 단단히 고정합니다. 흔들리게 붙이면 센서 자체의 흔들림이 진동으로 기록됩니다. 어느 방향으로 붙였는지(X 화살표가 앞쪽 등) 적어 두고, 기록마다 같은 방향을 유지하세요.

## 올리기와 기록

1. 아두이노 IDE에서 `amr_logger/amr_logger.ino`를 열고 보드·포트를 고른 뒤 업로드. 추가 라이브러리는 필요 없습니다(Wire만 사용).
2. 시리얼 모니터는 **닫습니다**. 열려 있으면 PC 기록기가 포트를 열 수 없습니다.
3. `실행/0_아두이노_기록.py` 위쪽의 `PORT`(예: `COM3`), `ROBOT`, `MINUTES`를 고치고 실행합니다.
4. 5초마다 기록 시간·줄 수·실제 샘플링(Hz)·전류·전압이 표시됩니다. **Hz가 500보다 많이 낮으면** 아두이노가 따라가지 못하는 것이니, 스케치의 `PERIOD_US`를 4000(250 Hz)으로 늘리세요. 이 경우 150 Hz 이상 고주파 특징은 쓸 수 없게 됩니다.

## 기록 요령

- **기록은 6분 이상.** 처음 5분이 그 기록의 "평소" 기준이 됩니다(진동 per_unit 기준, 전류 감시 모두).
- 처음 5분에는 실제 운행처럼 주행·정지·회전을 섞으세요. 평소에 없던 동작은 나중에 이상으로 보일 수 있습니다.
- 정상 기록은 날·배터리 충전 상태를 바꿔 여러 번 남기세요 (학습 데이터).
- 고장 실험(나사 풀기, 바퀴에 테이프로 무게 달기 등)은 `FAULT_KIND`, `FAULT_WHEEL`, `FAULT_SEVERITY`를 적고 기록합니다. 처음 5분을 정상으로 달리다가 고장을 내면, 고장이 시작된 시점부터만 라벨이 맞도록 파일을 나눠 기록하는 것이 좋습니다.

## 모터·엔코더 점검 (`motor_encoder_check/`)

모터나 엔코더가 이상하게 동작할 때, 부품을 하나씩 따로 돌려 배선 문제인지 코드 문제인지 가립니다.
스케치를 올리고 시리얼 모니터를 **115200 baud, '줄 끝 없음'**으로 연 뒤 글자 하나를 보냅니다. 처음에는 바퀴를 바닥에서 띄우세요.

| 보내는 글자 | 시험 | 정상이면 |
|---|---|---|
| `e` | 모터 끄고 10초 동안 엔코더 확인 (바퀴를 손으로 돌림) | 돌리는 쪽 펄스가 늘거나 줄고, A·B가 0/1로 바뀜 |
| `1`~`4` | 왼쪽 전진 / 오른쪽 전진 / 왼쪽 후진 / 오른쪽 후진 (명령 200, 2초) | 그쪽 바퀴만 돌고 그쪽 펄스만 바뀜. 전진과 후진의 부호가 반대 |
| `p` | 명령을 0 → 255로 올림 | 펄스가 0보다 커지는 PWM = 움직이기 시작하는 최소 명령 |
| `s` | 정지 | |

증상별 원인:

| 증상 | 원인 | 고칠 곳 |
|---|---|---|
| 시리얼 모니터에 깨진 글자 | 모니터 속도가 스케치와 다름 | 모니터를 115200으로 |
| 모터를 돌릴 때마다 "점검 스케치 시작" 줄이 다시 나옴 | 모터 전류로 아두이노 전원이 떨어져 재시작 | 아두이노는 USB로, 모터는 배터리로. GND만 공통 |
| 모터가 전혀 안 돎 | GND 미연결, 배터리 미연결, IN 핀 배선 | L298N GND ↔ 아두이노 GND ↔ 배터리 - |
| 255에서만 돌고 150에선 윙 소리만 | L298N이 약 2 V를 먹어서 낮은 명령으로는 힘이 부족 | 명령을 `p` 결과보다 크게 (예: 200) |
| 명령 크기와 상관없이 항상 최고 속도 | L298N의 ENA·ENB 점퍼가 꽂혀 있음 | 점퍼를 빼고 ENA → 9, ENB → 10 연결 |
| 한쪽이 반대로 돎 | 모터 두 선이 바뀜 | 그 모터의 OUT 두 선을 바꿔 꽂음 |
| `1`인데 오른쪽이 돎 | 왼쪽·오른쪽 배선이 바뀜 | IN·EN 선 또는 모터 선 정리 |
| `e`에서 펄스가 0, A·B도 안 바뀜 | 엔코더 전원(VCC·GND)이나 A선 문제 | 엔코더 VCC → 5V, GND, A → 2·3번 |
| `e`에서 A는 바뀌는데 펄스가 0 | A선이 2·3번이 아닌 핀에 꽂힘 (인터럽트 안 됨) | A상은 반드시 2번(오른쪽)·3번(왼쪽) |
| 한 방향으로 돌려도 펄스가 늘었다 줄었다 함 | B선이 빠졌거나 A·B가 같은 선 | B → 4(왼쪽)·5(오른쪽) |
| 전진할 때 오른쪽 펄스가 줄어듦 | 좌우 모터가 거울처럼 달려 있어 정상 | 고칠 필요 없음 (속도는 크기로 봄) |
| 모터가 멈춰 있는데 펄스가 계속 바뀜 | 엔코더 선에 모터 잡음이 섞임 | 엔코더 선을 모터 선과 떨어뜨림 |

## 보내는 형식

한 줄: `t_us,ax,ay,az,gx,gy,gz,shunt,bus` (센서의 원래 정수값)

| 값 | 설정 | PC에서 바꾸는 식 |
|---|---|---|
| `t_us` | `micros()` | 첫 줄부터 지난 초. 약 71분마다 0으로 돌아가는 것도 이어 붙임 |
| `ax..az` | ±4 g | ÷ 8192 → g |
| `gx..gz` | ±500 °/s | ÷ 65.5 → °/s |
| `shunt` | ±320 mV, 10 µV 단위 | × 10 µV ÷ 0.1 Ω → A |
| `bus` | 32 V 범위 | 위 13비트 × 4 mV → V |

MPU6050 저역통과 필터는 약 184 Hz로 설정했습니다. 500 Hz로 읽을 때 250 Hz가 넘는 떨림이 낮은 주파수로 잘못 섞여 들어오지 않게 하기 위해서입니다.
