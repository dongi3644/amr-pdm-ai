# 가상 데이터 결과값 (코드 점검용 · 성능 아님)

> **이 폴더의 숫자는 발표·성능 자료로 쓰지 않습니다.**
> 고장 신호를 사람이 직접 만들어 넣은 가상 데이터라, 잘 맞히는 것이 당연합니다.
> 이 결과가 보여 주는 것은 하나뿐입니다: **기록 → 검사 → 학습·평가 → 진단이 끝까지 오류 없이 돌고, 결과 형식이 맞다.**
> 실제 성능은 아두이노로 기록한 실측 CSV로 다시 재야 합니다.

- 무작위 가상 로봇 100대 시험 결과(%)는 [`로봇100대/`](로봇100대/README.md)에 있습니다 (2026-11-09, `가상테스트/test_robots.py`).
- 복잡한 고장까지 학습(160대)하고 어려운 로봇까지 넣어 시험(170대)한 결과는 [`복잡한고장_학습시험/`](복잡한고장_학습시험/README.md)에 있습니다 (2026-11-09, `가상테스트/test_complex.py`).
- 점검일: 2026-11-08
- 실행한 코드: 이 저장소의 `run.py check / train / diagnose` (설정은 기본값, 판정 주기 60초, 정상 기준 per_unit)
- 모델·보고서는 프로젝트의 `artifacts/`·`reports/`가 아닌 별도 폴더에 저장했고, 가상 CSV는 `data/`에 넣지 않았습니다.

## 가상 데이터를 만든 방법

아두이노 스케치가 보내는 것과 같은 한 줄(`t_us,ax,ay,az,gx,gy,gz,shunt,bus`, 센서의 원래 정수값)을 만들어
가짜 시리얼로 `pipeline/arduino.py`의 `record()`에 넣었습니다. 그래서 단위 변환과 CSV 저장까지 실제 기록 경로를 그대로 지났습니다.

| 로봇 | 기록 | 넣은 고장 |
|---|---|---|
| N1 ~ N4 | 10분 | 없음 (정상). 로봇마다 진동 크기·바퀴 속도·배터리 전압을 조금씩 다르게 |
| U1, U2 | 18분 | 앞 왼쪽 바퀴 불평형 |
| L1 | 18분 | 뒤 오른쪽 바퀴 체결부 풀림 |
| B1 | 18분 | 앞 오른쪽 바퀴 베어링 결함 (배터리를 낮게 시작해 7 V 아래로 내려가게) |

- 고장 로봇은 처음 6분 정상 → 고장 정도를 2분마다 0.3 → 0.5 → 0.7 → 0.8 → 0.9 → 1.0으로 올리며 파일을 나눠 기록
- 주행 패턴: 전진 7.7초 · 정지 2.3초 · 회전 3.4초 · 후진 4.1초 · 정지 1.9초 반복, 출발·정지 0.25초 가감속
- 일부러 넣은 문제: 연결 직후 깨진 글자, 0.1% 빠진 줄, 시각 흔들림(±15 µs), micros() 한 바퀴 돌기(N4), 분 단위 자동 정지(N1)

## 이 점검에서 찾아 고친 문제

| 문제 | 고친 곳 |
|---|---|
| 같은 로봇을 같은 초에 두 번 기록하면 앞 파일을 덮어씀 | `pipeline/arduino.py` (`_2`, `_3` 붙임) |
| 상태가 바뀐 주기에 진단 표의 추정 원인 칸이 한 주기 늦게 채워짐 | `pipeline/infer.py`, `pipeline/workflow.py` |

| 건너뛴 교차검증 겹·공통 기준을 고른 이유가 화면에 안 보임 | `run.py`, `pipeline/dataio.py` |

## 실측 데이터에서 조심할 점 (이 점검에서 알게 된 것)

- 처음 만든 가상 데이터에서는 출발 순간 샘플 하나가 조용한 정지 창에 섞여 충격처럼 보였고, 정상 점수의 꼬리가 길어져 9점 눈금이 실패했습니다.
  실제 기록도 **처음 5분에 주행·정지·회전을 여러 번 섞어야** 이런 창이 '평소'에 포함됩니다.
- 로봇이 2대(정상 1 + 고장 1)뿐이면 정상 로봇을 평가하는 겹은 학습할 정상 창이 모자라 빠집니다. 정상 기록을 이름 2개 이상(예: R1_정상A, R1_정상B)으로 나눠 남기세요.
- 고장 종류마다 기록이 1대뿐이면 교차검증의 원인 정확도는 잴 수 없습니다 (위의 B1, L1처럼 채점 제외로 표시됨).
