# 엔코더 성능 개선: 최종 시험 (가상 로봇 · 코드 점검용 · 성능 아님)

> 진동·고장·엔코더 신호를 사람이 식으로 만든 가상 로봇 결과입니다. 실제 로봇 성능이 아닙니다.
> 전류·전압은 지금처럼 **감시용으로만** 쓰고 AI 입력에는 넣지 않았습니다.

## 과대적합을 막은 방법

| 장치 | 내용 |
|---|---|
| 개발용과 최종 시험용 로봇 분리 | 개선은 개발용 가상 로봇(seed 3001)에서만 확인하고 고쳤습니다. 최종 시험 로봇(seed 4001)은 **한 번도 보지 않은 상태에서 딱 한 번** 돌렸습니다. |
| 고치는 횟수 제한 | 개발용에서 3번 고친 뒤 멈췄습니다. 최종 시험 결과를 보고 다시 고치지 않았습니다. |
| 모델 크기는 그대로 | 오토인코더·랜덤포레스트 설정은 바꾸지 않았습니다. 새로 넣은 바퀴 이상 점수는 학습할 것이 없는 단순한 규칙입니다. |
| 눈금 보정은 학습에 안 쓴 로봇으로 | 3점(정상 99.5%) 눈금은 학습에 쓰지 않은 정상 로봇으로 맞췄습니다. |
| 개발용과 최종 결과 비교 | 개발용 93.3%, 최종 91.1%로 비슷합니다. 개발용 로봇에 맞춰진 정도가 크지 않다는 뜻입니다. |

## 무엇을 바꿨나 (개선 전 = 직전 GitHub 버전)

1. **바퀴 속도 → 바퀴 상대 속도.**
   - 바퀴 속도는 주행·정지·회전에 따라 크게 바뀌어 고장과 섞입니다.
   - 그래서 다른 세 바퀴보다 얼마나 빠르거나 느린지(비율)만 봅니다. 바퀴가 도는 구간만으로 계산합니다.
2. **바퀴 이상 점수 추가 (주 모델 = 오토인코더 + 바퀴).**
   - 오토인코더는 특징 47개의 복원 오차를 평균 내므로, 바퀴 하나에 생긴 이상이 묻히기 쉽습니다.
   - 그래서 네 바퀴 중 **한 바퀴만 외톨이처럼 튀는 정도**를 따로 계산합니다.
   - 두 점수를 같은 눈금으로 맞춘 뒤 큰 쪽을 건강 점수로 씁니다.
   - 네 바퀴가 함께 흔들리면(거친 바닥) 작게 나오도록 했습니다.
   - `config.WHEEL_SCORE = False`로 끌 수 있습니다.

## 대가와 남은 약점 (그대로 적음)

1. **오경보가 생겼습니다.**
   - 중간에 바닥이 거칠어진 정상 로봇 1대에서 '주의'가 떴습니다.
   - 정상 창이 3점을 넘는 비율도 0.5%에서 4%로 늘었습니다.
   - 원인: 3점 눈금을 맞춘 정상 로봇들(보정용)에 '바닥이 바뀌는 기록'이 없었습니다. 그래서 처음 보는 조건에서 바퀴 점수의 눈금이 덜 맞았습니다.
   - 실측에서 줄이려면 정상 기록을 여러 바닥·짐 조건으로 남겨야 합니다. 그러면 보정용 로봇에도 그런 조건이 들어갑니다.
2. **간헐 고장은 여전히 0%입니다.** 1분 판정 점수가 중앙값이라 가끔 나타나는 고장이 묻힙니다. `PERIOD_QUANTILE`로 바꿀 수 있지만, 실측 정상 기록을 보고 정해야 합니다.
3. **남은 시간 예측은 조금 나빠졌습니다.**
   - 점수가 더 일찍 오르면서 예측 횟수가 25회에서 58회로 늘었고, 그만큼 어려운 예측(먼 미래)이 많아졌습니다.
4. **고장이 바퀴 속도에 주는 영향은 사람이 정한 가정입니다.**
   - 예: 베어링이면 15% 느려지고, 풀림이면 속도가 흔들린다고 정했습니다.
   - 실제 로봇에서 얼마나 도움이 되는지는 실측 교차검증으로 다시 재야 합니다.
