# AMR 고장예지 AI — 실측 데이터 전용 (진동만 사용)

가상(시뮬레이션) 데이터를 전혀 쓰지 않는 버전입니다. 시뮬레이터 코드가 없고, 모든 모델은 `data/`에 넣은 실측 CSV로만 학습·평가합니다. 시뮬레이션 버전은 옆 폴더 `amr_pdm/`에 그대로 있습니다.

**쓰는 데이터는 바퀴 4개의 진동뿐입니다.** 전류·배터리·속도·온도는 쓰지 않습니다. 없는 값을 기본값이나 다른 바퀴 값으로 채워 넣지도 않아서, 필요한 열이 없으면 추측하지 않고 오류로 알려 줍니다.

## 실행

| 순서 | 실행 파일 (`실행/`) | 명령 | 결과 |
|---|---|---|---|
| 1 | `1_환경설치.py` | | `.venv` 생성, 패키지 설치 |
| 2 | `2_데이터_검사.py` | `python run.py check` | 형식 검사, 정상 기준 방식 결정 |
| 3 | `3_학습_평가.py` | `python run.py train` | 로봇 단위 교차검증 → `reports/`, 최종 모델 → `artifacts/` |
| 4 | `4_진단.py` | `python run.py diagnose` | 로봇별 진단 (분 단위) → `reports/diagnose/` |

VS Code는 이 폴더를 열고 왼쪽 "실행 및 디버그"에서 고르면 됩니다. Visual Studio는 폴더 열기 → 실행 파일 오른쪽 클릭 → 시작 항목으로 설정 → Ctrl+F5.

공통 옵션: `--path 경로`(기본 `data`), `--fs 1000`(time 열이 없을 때 센서의 실제 샘플링 Hz), `--period-s 60`(판정 주기 초), `--baseline auto|per_unit|reference`, `train --no-eval`(교차검증 없이 최종 모델만).

## AI 모델 구성

```
CSV (바퀴 4개 진동)
  → 1초 창 → 특징 48개 (바퀴마다 6개 + '이 바퀴 − 나머지 세 바퀴 평균' 6개)
  → [구간별 정상 기준] z-score  (로봇마다 / 정상 로봇 공통)
       ├→ [오토인코더] 건강 점수 0~ (3 주의 · 6 경고 · 9 정지 위험)
       │      → 판정 주기(기본 1분) 중앙값 → 상태 (2번 연속일 때만 변경)
       │      → [칼만 필터] 정지 위험까지 남은 시간(분) + 90% 범위
       └→ [랜덤포레스트] 고장 종류(+바퀴) 확률 → [SHAP] 판단 근거 상위 3개
```

| 역할 | 모델 | 설정 | 학습 데이터 |
|---|---|---|---|
| 정상 기준 | 구간별 평균·표준편차 | 표준편차 하한 = 0.001 + 평균의 5% | 로봇의 처음 5분 또는 정상 로봇 공통 |
| **이상 감지 (주 모델)** | **오토인코더** (MLP 48-24-6-24-48, tanh) | 조기 종료, 정상만 학습 | 정상 창 |
| 이상 감지 비교 | z-score 평균, ECOD, Isolation Forest, PCA(6성분) | ECOD·Isolation Forest는 PyOD가 기본으로 권하는 기준선 | 정상 창 |
| 건강 점수 눈금 | 분위수 보정 | 정상 99.5% = 3, 고장 기준 창 중앙값 = 9 (로그 눈금) | 학습에 안 쓴 정상 로봇 + 고장 창 |
| 원인 분류 | 랜덤포레스트 | 150그루, 잎 최소 3, 클래스 균형 | 고장 라벨 창 (정도 0.25 이상) + 정상 |
| 판단 근거 | SHAP TreeExplainer | 판정 클래스 기여도 상위 3개 | — |
| 남은 시간 | 칼만 필터 (수준·기울기 2상태) | 잡음 값을 학습 고장 기록으로 격자 탐색 | 9점까지 간 학습 고장 로봇 |
| 비교 | 추세선 (최근 6주기 직선) | — | — |

### 특징 48개

| 종류 | 바퀴마다 | 잡는 고장 신호 |
|---|---|---|
| RMS (진동 크기) | 1 | 전반적으로 흔들림이 커짐 — 불평형, 풀림 |
| 첨도, 크레스트 | 2 | 뾰족한 충격이 섞임 — 베어링 표면 손상의 초기 신호 |
| 저(1~20 Hz)·중(20~150 Hz)·고(150 Hz 이상) 주파수 에너지 | 3 | 어느 대역이 커졌는가 — 고장 종류마다 다름 |
| 위 6개의 `dev_` (이 바퀴 − 나머지 세 바퀴 평균) | 6 | 노면처럼 모든 바퀴에 같이 오는 영향은 빠지고, 한 바퀴에만 생긴 고장이 남아 고장 바퀴 위치를 짚음 |

바퀴 4개 × 12 = 48개. 속도 데이터가 없으므로 회전 주파수(1X) 특징은 계산하지 않습니다(속도를 가정하면 임의 값이 되기 때문).

### 판정 주기 (회차 대신)

정해진 경로를 반복하지 않는 운행이라 '회차'를 쓰지 않습니다. 1초 창의 건강 점수를 **판정 주기**(`config.PERIOD_S`, 기본 60초)마다 묶어 중앙값으로 상태를 정하고, 2번 연속(기본 2분)일 때만 상태를 바꿉니다. 정상 기준(per_unit)은 처음 5주기(5분), 남은 시간과 여유 시간은 모두 분으로 표시합니다. `python run.py train --period-s 30`처럼 바꿀 수 있고, 학습 때 정한 값은 모델에 저장되어 진단할 때 그대로 쓰입니다. 기록이 끊긴 시간(로봇이 꺼져 있던 시간)은 건너뛰고 기록된 시간 기준으로 셉니다.

## 데이터 형식

CSV 한 줄 = 진동 샘플 하나, 파일 하나 = 로봇 1대(같은 `robot` 값의 파일 여러 개는 이어 붙임).

```csv
time,segment,fl_vib,fr_vib,rl_vib,rr_vib
0.000,복도A,0.0132,-0.0071,0.0040,0.0025
0.001,복도A,0.0094,0.0023,-0.0012,0.0031
```

**필수 열**

| 열 | 설명 | 없을 때 |
|---|---|---|
| `fl_vib`, `fr_vib`, `rl_vib`, `rr_vib` | 앞 왼쪽·앞 오른쪽·뒤 왼쪽·뒤 오른쪽 바퀴 진동 [g]. `vib_fl`, `front_left_vib`, `앞왼쪽진동`처럼 이름이 조금 달라도 알아듣습니다(`config.WHEEL_ALIASES`) | **오류.** 한 바퀴라도 없으면 다른 바퀴 값으로 채우지 않고 멈춥니다 |
| `time` | 시각 [초] 또는 날짜·시각. 샘플링 주파수를 여기서 계산 | `--fs`로 실제 샘플링을 알려 주면 그걸로 시각 계산, 둘 다 없으면 **오류** |

진동 샘플링은 100 Hz 이상이어야 하고, 300 Hz보다 낮으면 고주파(150 Hz 이상) 특징이 거의 비게 된다고 경고합니다.

**선택 열** (없어도 됨, 값을 만들어 넣지 않음)

| 열 | 설명 | 없을 때 |
|---|---|---|
| `segment` | 구간(장소, 노면) | 전체를 한 구간으로 보고 기준을 만듦 (장소별 노면 차이를 걸러내지 못함) |
| `bump` | 문턱 통과 0/1 | 문턱 순간을 판정에서 빼지 못함 |
| `robot` | 로봇 이름 | 파일 이름 |
| `fault_kind`, `fault_wheel`, `fault_severity` | 라벨 (학습·평가용). `fault_wheel`은 `fl`·`앞 오른쪽`·`front-left` 등 | 라벨 없는 로봇은 정상으로 보고 학습·평가. 고장 라벨이 하나도 없으면 원인 분류·남은 시간 예측을 하지 않음 |

열 이름이 다르면 `config.py`의 `COLUMN_ALIASES`에 추가하세요.

### 정상 기준 방식 (`--baseline`)

- **per_unit**: 로봇마다 처음 5분(5주기)으로 그 로봇만의 구간별 기준을 만듭니다. 운행을 정상 상태에서 시작하는 실제 로봇 기록에 맞습니다.
- **reference**: 학습용 정상 로봇들을 모아 공통 기준을 만듭니다. 처음부터 고장인 기록에 필요합니다.
- **auto** (기본): 처음 5분에 고장 라벨이 있거나 기록이 그보다 짧은 로봇이 있으면 reference.

reference 방식은 정상 로봇이 적으면 처음 보는 정상 로봇을 이상으로 봅니다. 정상 로봇은 3대 이상, 가능하면 5대 이상 넣으세요.

## 설계 근거 (참고한 신뢰할 수 있는 자료)

1. **평가는 로봇 단위로 나눈다.** 같은 장비의 창이 학습과 평가에 섞이면 장비 고유 특성을 외워 성능이 부풀려집니다. 장비 단위 분할의 중요성을 다룬 연구: Vieira et al., *Towards a more realistic evaluation of machine learning models for bearing fault diagnosis*, [arXiv:2509.22267](https://arxiv.org/abs/2509.22267v1) (2025). → `workflow.cross_validate`는 평가 로봇을 정상 기준·눈금 보정·학습 어디에도 쓰지 않습니다.
2. **비교 기준선은 검증된 기본값을 쓴다.** 이상 감지 라이브러리 [PyOD](https://pypi.org/project/pyod/)와 벤치마크 ADBench 저자들은 잘 모를 때 Isolation Forest와 ECOD를 기본으로 권합니다. → 오토인코더가 이 둘보다 나은지 같은 조건에서 비교합니다. ECOD는 의존성을 늘리지 않으려고 논문(Li et al., TKDE 2022) 정의대로 직접 구현했습니다.
3. **건강 지표의 품질을 잰다.** 예지 정비에서 건강 지표는 단조성·추세 일치도·고장 시점 일관성으로 평가합니다 ([MathWorks Predictive Maintenance Toolbox](https://ch.mathworks.com/help/predmaint/ug/feature-selection-for-remaining-useful-life-prediction.html)). → 진행형 고장 기록이 있으면 `health_indicator` 항목에 계산됩니다. 기록이 적으면 이 값은 믿기 어렵습니다.
4. **남은 수명 예측은 상태 추정 문제로 푼다.** NASA의 예지 정비 라이브러리 [ProgPy](https://github.com/nasa/progpy)도 상태 추정 + 예측 구조입니다. 여기서는 데이터가 적은 상황에 맞춰 2상태 칼만 필터만 쓰고, 잡음 값은 학습 데이터로 맞춥니다.

## 결과를 볼 때 주의

- `reports/`의 수치는 **로봇 단위 교차검증** 결과입니다. 학습에 쓴 로봇을 `diagnose`로 진단한 결과는 성능이 아닙니다.
- 로봇이 적으면 수치가 크게 흔들립니다. 몇 대로 평가했는지 함께 발표하세요.
- 고장 정도(`fault_severity`) 라벨이 없으면 9점 눈금은 고장 창 전체의 중앙값으로 맞추고, 정지 위험 전 경고 여유는 계산하지 않습니다.
- 진동만 쓰므로 속도가 크게 바뀌는 운행에서는 속도 변화가 이상으로 보일 수 있습니다. 정상 기록에 여러 속도의 운행이 충분히 들어 있어야 오경보가 줄어듭니다.
