# third_model — AMR 구동부 고장 예지 AI

배송 로봇(AMR) 바퀴 구동부에 싼 센서(MPU6050 진동 · INA219 전류 · 바퀴 엔코더)를 달고, **고장이 났는지 · 어느 바퀴의 무슨 고장인지**를 1분마다 알려 주는 AI입니다.
학습 때 본 고장(아는 고장)과 **학습 라벨에 없던 고장(처음 보는 고장)**을 함께 다룹니다. 2026 DSC 공유대학 × KT AI 활용 지역문제 해결 캠프 참가작.

- 코드 파일마다 하는 일: [코드_파일_설명.md](코드_파일_설명.md)
- 최종 성능표와 시험 조건만 따로: [최종_성능과_시험_조건.md](최종_성능과_시험_조건.md)
- 실측 데이터 두는 곳: [data/README.md](data/README.md)

## 1. 모델 구성 (AI 2개)

```
센서 기록 → 1초씩 자르기 (로봇마다 처음 5분 = 평소, 모든 값을 '평소 대비 z값'으로)
 → 특징 121개: 진동 24 (ax·ay·az·gz) · 바퀴 11 · 엔코더 1회전 속도 모양 8 · 주파수 모양 72 · 뾰족함 3 · 1회전 박자 3
 ├→ AI ① 주파수 모양 오토인코더 (비지도 딥러닝, 정상만 학습)   → 처음 보는 고장
 ├→ AI ② 랜덤포레스트 (지도, 고장 라벨 + 가상 이상으로 학습)    → 아는 고장 + 원인
 └→ 바퀴 점수 (규칙, AI 아님): 바퀴 하나만 튀는 정도 (속도 흔들림 · 상대 속도 · 앞뒤 차이 · 1회전 속도 모양)
      셋 중 큰 값 = 건강 점수 → 1분마다 정상 · 주의 · 경고
      주의 이상이면 AI ②가 원인 (종류 · 바퀴 또는 '처음 보는 이상') + SHAP 근거 3개
 전류 · 전압 → 규칙 감시 (전류 높음, 배터리 7.0 V 아래, 사용량 mAh)
```

| 부분 | 내용 |
|---|---|
| gz(회전 속도) | 각속도 센서 값이 없으면 **좌우 엔코더로 계산** (오른쪽 − 왼쪽 바퀴 속도 ÷ 바퀴 사이 거리) |
| 1회전 박자 | 충격(20 Hz 이상 떨림의 크기)이 바퀴 1회전 간격으로 되풀이되는 정도. 바퀴 찍힘 0.4~0.8, 체결 풀림 · 바닥 ≈ 0 |
| 엔코더 1회전 속도 모양 | 최근 10초를 **바퀴 각도(펄스 수 ÷ 330의 나머지)별로 겹쳐 평균**한 '그 각도를 지나는 데 걸린 시간'. 바퀴마다 완만한 출렁임(1차) · 좁은 패임(나머지)을 다른 세 바퀴와 비교. 바퀴 찍힘 · 휜 림처럼 바퀴에 붙은 결함은 같은 각도에서 매번 느려짐. 바닥 · 속도 변화는 네 바퀴 공통이라 빠짐 (엔코더 4개일 때만) |
| 주파수 모양 | 축마다 2~235 Hz를 24칸으로 나눈 **'그 칸 에너지 ÷ 전체 에너지'**. 실측(속도 5)에서 바닥은 20~40 Hz(2.85배), 테이프 고장은 160~235 Hz(2.04배)가 더 커짐. 바닥만 바뀌어도 비율이 바뀌므로 크기 특징과 함께 씀 |
| AI ① | 신경망 78 → 32 → 8 → 32 → 78 (주파수 모양 72 + 뾰족함 3 + 1회전 박자 3). 되살리기 오차 = 이상 점수 |
| AI ② | 결정나무 150그루. 항목 14개 = 정상 · 아는 고장 12 (바퀴 불균형 · 체결 풀림 · 마찰 증가 × 바퀴 4) · 처음 보는 이상. 감지는 '정상이 아닐 확률', 원인은 같은 확률 |
| 건강 점수 눈금 | 학습에 안 쓴 정상 로봇의 99.5% 지점 = 3점, 고장 정도 0.8 = 9점. 모델마다 눈금을 맞춘 뒤 큰 값 |
| 1분 판정 | 1분 점수 = max(1초 점수의 중앙값, 상위 10% 지점 × 0.65) (간헐 고장용). **2.0점 이상 주의, 6점 이상 경고**, 2번 연속일 때 바꿈 (검증 로봇으로 고른 값) |
| 원인 | 1초 점수가 주의 문턱 이상인 창만 · 최근 3분 평균 · 종류(바퀴 4개 합) 먼저 · 확신 0.3 미만이면 '원인 미확정' |

## 2. 처음 받는 사람: 이 폴더 하나만 있으면 됩니다

1. **Python 3.9 이상** 설치 (python.org, 설치할 때 "Add python.exe to PATH" 체크)
2. 이 폴더(`third_model`)를 VS Code로 열기 → `실행 및 디버그`(Ctrl+Shift+D) → **`1. 환경 설치`** (또는 `python 실행/1_환경설치.py`)
   → `.venv` 가상환경을 만들고 `requirements.txt` 설치 (약 1분, PyTorch 필요 없음)
3. 팀 실측 폴더 4개를 `data/` 아래에 폴더째로 넣기 ([data/README.md](data/README.md))
4. 실행 목록에서 고르기

| 항목 | 하는 일 | 시간 |
|---|---|---|
| `가상 성능 시험` | 실측 보정 가상 로봇으로 학습 → 학습에 쓰지 않은 가상 시험 로봇으로 채점. **기본값이 5-1절 최종 결과의 조건** (새 로봇 166대 · 세기에 추가 배율 0.5~1.0 · 고장 93대 중 39대가 처음 보는 고장) | 약 15분 |
| `가상 성능 시험: 예전 4조건 모두` | 5-2절의 4조건 (`--cond all`) | 약 30분 |
| `가상 성능 시험: 빠른 확인` | 같은 시험을 로봇 수만 줄여 (작동 확인) | 약 3분 |
| `가상 로봇 몇 대 CSV로 저장` | 가상 로봇 6대(정상 1 + 고장 5종류)를 CSV로 → `가상테스트_결과/가상로봇_CSV/` | 약 1분 |
| `3. 지난 결과 다시 보기` | 실험 없이 마지막 결과의 요약표 · 그림만 다시 봄 | 몇 초 |
| `4. 진단` | CSV(가상 로봇 CSV 등) → 1분 진단표 · 그래프 (`run.py diagnose`) | – |

터미널로 하려면 (third_model 폴더에서):
```
python 가상테스트/성능시험.py --jobs 8
```
기본값 = `--seed 2031 --val-scale 1.0 --test-scale 2.0 --cond 0.5-1.0 --test-shift 1` (5-1절 최종 결과의 조건).
끝나면 터미널에 **한눈에 보는 요약표**가 나오고, `가상테스트_결과/성능시험/`에 `결과_요약.txt`(같은 글) · `결과_그림.png`(막대그림) · `결과.json`(전체 숫자)이 저장됨. 실험 없이 다시 보려면 `python 가상테스트/성능시험.py --show 가상테스트_결과/성능시험` (VS Code `3. 지난 결과 다시 보기`). 실측 폴더를 다른 곳에 두었으면 `--g3 · --yg · --fault`로 알려 줌

## 3. 입력 데이터 (CSV)

팀 기록 형식 `t_us, ax, ay, az, mV, mA, spd, enc2, label`을 그대로 읽습니다 (표준 열 이름 `time, ax, ay, az, current, voltage, motor_cmd, enc_fl · enc_fr · enc_rl · enc_rr, fault_kind · fault_wheel · fault_severity`도 됨).

| 열 | 뜻 | 쓰임 |
|---|---|---|
| `t_us` / `time` | 시각 (µs / 초) | 1초 창 · 샘플링 계산 (약 480 Hz) |
| `ax` `ay` `az` | 차체 가속도 (센서 정수값 8192 = 1 g, 또는 g) | **진동 특징 · 주파수 모양 (필수)** |
| `enc1~4` / `enc_fl~rr` | 바퀴 엔코더 (1바퀴 330펄스). 누적 · 샘플마다 · 속도 어느 형식이든 자동 판별 | 바퀴 특징, **gz 계산**(좌우가 다 있을 때) |
| `spd` / `motor_cmd` | 모터 명령 (속도 단계) | 속도 단계마다 평소 기준을 따로 |
| `mV` `mA` | 배터리 전압 · 전체 전류 | 규칙 감시 (AI에는 안 넣음) |
| `label` / `fault_*` | 고장 라벨 (학습용) | 진단에는 필요 없음 |

한 기록은 **6분 이상** (처음 5분이 그 로봇의 평소 기준). 실측 엔코더가 enc2 하나뿐이면 바퀴끼리 비교하는 특징 · 바퀴 점수 · gz는 빠지고 진동 + enc2 특징으로 진단합니다.

## 4. 가상 데이터는 어떻게 만들어지나

실측 고장 기록이 테이프 불균형 20초 하나뿐이라, **실측 기록을 재료로 가상 로봇을 만들어** 학습 · 시험합니다.
가상 로봇은 실행할 때마다 컴퓨터 안(메모리)에서 새로 만들어지고 파일로 저장되지 않습니다 (몇 대만 보고 싶으면 `가상테스트/가상로봇_저장.py`).
같은 실측 데이터 · 같은 seed(`성능시험.py` 기본 2031)면 누구 컴퓨터에서든 같은 로봇이 만들어집니다.

**가상 데이터를 만드는 파일**

| 파일 | 하는 일 |
|---|---|
| `가상테스트/실측보정_로봇.py` | **가상 로봇을 실제로 만드는 곳** (`RealPools` 실측 조각 묶기 · 나누기, `FaultModel` 실측 불균형 증가분, `make_table` 로봇 1대 만들기) |
| `가상테스트/sim_robots.py` | 로봇 조건 정하기 (고장 종류 · 바퀴 · 시작 · 진행 · 간헐 · 복합, 헷갈리는 정상) |
| `가상테스트/성능시험.py` | 학습 · 검증 · 시험 로봇을 만들어 학습하고 채점 |
| `가상테스트/가상로봇_저장.py` | 가상 로봇 몇 대를 CSV로 저장 (열어 보기용) |
| `pipeline/augment.py` | 학습 때만 쓰는 가상 이상 (4-4) |

### 4-1. 재료: 팀 실측 폴더 4개
| 폴더 | 쓰임 |
|---|---|
| 정상 데이터_공3옥상 · 공3옥상(11.16) · 욧골(11.15) | 정상 진동 · 전류 · 전압의 **조각** (바닥 2곳 × 속도 5 · 7 · 정지) |
| 고장 데이터_욧골 | 앞 오른쪽 바퀴 테이프(불균형) → **고장으로 늘어난 진동**을 잼 |

- 실측 파일을 **파일 단위로 학습 · 검증 · 시험**으로 나눔 (`RealPools.split`). 주행 조각은 학습에 안 쓴 파일에서만 뽑음. 단, 정지 기록 3개 · 테이프 고장 모양 · 생성 방식은 학습과 공유
- 불균형 고장의 모양(`FaultModel`): 학습 몫의 욧골 정상과 테이프 고장의 주파수 에너지를 비교해, 늘어난 부분을 **바퀴 회전 1 · 2 · 3배 성분**(사인파 세기)과 **나머지 잡음 모양**으로 나눠 기억

### 4-2. 로봇 1대 만들기 (`가상테스트/실측보정_로봇.py`의 `make_table`)
1. **조건 정하기** (`sim_robots.py`의 `random_spec` · `complex_spec`): 기록 길이(약 10~21분), 바닥 · 속도, 고장이면 종류 · 바퀴 · **시작 시각(6~8분)** · 진행 시간(6~12분) · 최종 고장 정도(보통 0.5~1.0, 급성 0.6~1.0, 약한 고장 0.3~0.5) · 세기 배율(0.7~1.3, 약한 고장 0.6~1.0). 최종 세기 = 고장 정도 × 배율
2. **주행 계획**: 15~45초 달리고 2~4초 멈춤을 반복. '바닥 바뀜' · '속도 바뀜' 로봇은 7~10분째부터 다른 바닥 · 속도
3. **정상 진동 · 전류 · 전압**: 같은 (바닥, 속도) 실측 기록에서 **2~6초 조각을 뽑아 이어 붙임** (이음매는 부드럽게, 조각마다 크기 ±5%, 로봇 전체 ±15%, 축마다 ±15%). 멈춘 구간은 실측 정지 조각. 짐을 실으면 흔들림 · 전류 증가, 저전압 정상은 전압을 낮춤
4. **고장 진동 더하기** (고장 정도는 시작 때 0.1 → 최종 정도까지 점점 커짐, 속도가 빠를수록 큼)

| 고장 | 만드는 방법 | 근거 |
|---|---|---|
| 바퀴 불균형 | 실측 테이프 고장의 **늘어난 진동** 그대로: 그 바퀴 회전 위상에 맞춘 1 · 2 · 3배 사인파 + 같은 주파수 모양의 잡음 | **실측 보정** |
| 체결 풀림 | 바퀴 회전에 맞춰 불규칙하게 '딱' 하는 충격(60 Hz로 울림) | 가정 (에너지는 실측 불균형과 같게) |
| 마찰 증가 (베어링 · 걸림) | 200 Hz 부근 좁은 대역 잡음 + 전류 증가 + 그 바퀴가 조금 느려짐 | 가정 (에너지는 같게) |
| 기어 마모 *(시험 전용 · 처음 보는 고장)* | 바퀴 회전 × 48배 순음 (속도 5에서 108 Hz) + 회전 옆띠 | 가정 |
| 바퀴 찍힘 *(시험 전용 · 처음 보는 고장)* | 바퀴 1회전에 한 번 '쿵'(35 Hz로 울림), 그 바퀴가 그때 잠깐 느려짐 | 가정 |
| 새 주파수 베어링 *(시험 전용)* | 마찰 증가를 120 · 160 Hz로 | 가정 |

   - 고장 바퀴 위치에 따라 센서(차체)까지 거리 · 방향만큼 축별 세기가 달라짐 (실측은 앞 오른쪽, 나머지 바퀴는 가정한 비율)
   - 샘플링 절반(240 Hz)을 넘는 주파수는 실제 센서처럼 접혀 들어감 (320 Hz → 160 Hz)
   - 고장 진행 방식: 점진 · 급성(한 번에 큼) · 간헐(5~30초 켜짐 / 10~60초 꺼짐) · 복합(두 바퀴) · 약한 고장
5. **엔코더 4개**: 모터 명령으로 정한 바퀴 회전(속도 5 = 2.25 Hz) × 330펄스, 평소 속도 흔들림 4~5%. 고장 바퀴는 불균형이면 1회전마다 ±12% 출렁임, 마찰이면 느려짐, 풀림이면 흔들림 증가
6. **센서 형식으로**: 가속도 1/8192 g 단위, 전류 1 mA, 전압 4 mV 단위로 반올림, 엔코더는 16비트처럼 넘침. 각속도 열은 만들지 않음 → 읽을 때 엔코더로 gz 계산

### 4-3. 학습 · 검증 · 시험 로봇 구성 (`가상테스트/성능시험.py`)
| 역할 | 구성 | 쓰임 |
|---|---|---|
| 학습 | 아는 고장 3종류 × 바퀴 4 × 점진 고장 + 정상 · 바닥 바뀜 · 짐 실음 · 저전압 정상 · 속도 바뀜 + 급성 · 간헐 · 복합 · 약한 · 속도 다름 고장 (기본 약 50대) | 모델 학습 |
| 검증 | 시험과 같은 구성, **아는 고장만**, 검증 몫 실측 조각 | 판정 문턱 · 연속 횟수 · '원인 미확정' 기준 고르기 |
| 시험 | 일반 로봇 + 복잡한 고장 · 헷갈리는 정상, **시험 몫 실측 조각** (`--test-scale 2.0`이면 조건마다 약 170대) | 성능 채점 |

시험 조건: 고장 로봇의 **절반을 처음 보는 고장**(기어 마모 · 바퀴 찍힘 · 새 주파수 베어링)으로 바꾸고(두 번째 고장은 지움), 세기 배율에 추가로 1.0배(기본) · 1.2~1.5배(충분히 진행된 고장) · 0.4~1.0배 무작위(현실 조건)를 곱해 각각 채점.

### 4-4. 학습 때만 넣는 '가상 이상' (`pipeline/augment.py`)
랜덤포레스트가 '배운 고장'만 알지 않도록, 학습용 정상 로봇 복사본의 진동에 무작위 모양을 넣어 **'처음 보는 이상'** 라벨로 함께 가르칩니다 (Outlier Exposure, Hendrycks 외 2019).
모양: 좁은 대역 잡음(5~235 Hz) · 순음 + 배음 · 주기 충격 · 바퀴 회전 × k배 순음(k = 1~80) · 1회전에 m번 충격(m = 1~4). 세기는 그 창 진동 에너지의 0.15~1.5배, 정상 창의 절반에 넣음.
**주의**: 마지막 두 모양은 시험의 기어 마모 · 바퀴 찍힘과 같은 계열이라, 처음 보는 고장 점수가 실제보다 좋게 나올 수 있습니다.

## 5. 가상 시험 결과 (11/20 최종, 실측 성능 아님)

### 5-1. 최종 (엔코더 1회전 속도 모양 추가 후)

조건: 세기에 추가 배율 0.7~1.0 무작위 + **고장 로봇 절반이 처음 보는 고장**(기어 마모 · 바퀴 찍힘 · 새 주파수 베어링). 검증 로봇 83대(아는 고장만)로 판정 설정을 고르고, 학습에 쓰지 않은 가상 시험 로봇 166대로 잼 (`--val-scale 1.0 --test-scale 2.0 --cond 0.7-1.0`).

| 시험 로봇 (166대) | 정답률 | 아는 고장 감지 | 처음 보는 고장 감지 | 오경보 | 원인 맞음 |
|---|---|---|---|---|---|
| **새 로봇 · 새 실측 나누기** (`--seed 2031`, 이 코드로 처음 시험) | **98.2%** | 100% (56/56) | 92.9% (39/42) | 0.0% (0/68) | 92.6% |
| **새 로봇, 더 약한 고장 (추가 배율 0.5~1.0)** (같은 모델 · 설정, 다른 시험 로봇) · **최종 = `가상 성능 시험` 기본값** | **97.6%** | **96.3%** (52/54) | **94.9%** (37/39) | 0.0% (0/73) | **96.6%** |
| 고치는 데 본 로봇 (`--seed 2027`) | 98.8% | 100% (43/43) | 95.7% (45/47) | 0.0% (0/76) | 97.7% |
| └ 같은 로봇, 고치기 전 | 96.4% | 97.7% | 93.6% | 2.6% | 97.7% |

- **기준으로 쓰는 숫자는 위 두 줄(새 로봇)**. 단, 개발 중 시험 결과를 보고 특징과 시험 조건을 바꿨으므로 완전히 독립된 시험은 아님.
- 위 두 줄을 쓰는 이유: 아래 두 줄은 이 로봇들의 결과를 보며 코드를 고쳤으므로 좋게 나올 수 있음
- 100% · 0%는 해당 로봇을 모두 맞힌 값 (예: 56대 중 56대). 대수가 적으니 '98~100%'로 읽는 게 맞음
- **95% 미만 (남은 과제)**
  - 처음 보는 고장 감지 92.9%: 놓친 3대 = 바퀴 찍힘 2대(세기 배율 0.68 · 0.73), 간헐로 나타나는 새 주파수 베어링 1대(배율 0.83). 엔코더 1회전 속도 모양으로 바퀴 찍힘 감지가 9/12 → 10/12
  - 원인 92.6%: 체결 풀림을 '바퀴 불균형'으로 3대, 기어 마모를 '마찰 증가'로 2대, 복합 고장 1대, 바퀴 찍힘을 '체결 풀림'으로 1대. 1회전 속도 모양이 풀림의 불규칙한 속도 흔들림을 불평형처럼 보는 경우가 생김
- 더 약한 고장 줄 (최종): 첫 줄과 같은 모델 · 검증 설정으로 시험 로봇만 새로 만들어 채점함 (`--reuse 가상테스트_결과/작은실험_세기07_6_새로봇`, 약 2분). 학습 · 검증은 seed로 정해지므로 `python 가상테스트/성능시험.py`(기본값)로 처음부터 돌려도 같은 모델 · 같은 시험 로봇이 됨. 놓친 4대 = 바퀴 찍힘 2대(최종 세기 0.46 · 0.22), 마찰 증가 1대(0.20), 바퀴 불균형 1대(0.23) → 3대는 약하고 0.46은 중간 정도. 원인 오류 3대 = 체결 풀림 1대 · 바퀴 찍힘 2대를 '바퀴 불균형'으로
- 판정 설정 (검증으로 고름): 1분 중앙값 · 간헐 0.65 · 2번 연속 · 주의 2.0점 · 원인 미확정 0.3

### 5-2. 이전 코드 (엔코더 1회전 속도 모양을 넣기 전, 같은 날 오전)

주 모델 · 판정 설정 · '원인 미확정' 기준은 모두 **검증 로봇(약 80대, 아는 고장만)**으로 고르고, 시험은 **학습에 쓰지 않은 가상 시험 로봇 약 250대씩**으로 잼 (`--val-scale 1.0 --test-scale 3.0`).

| 조건 (약 250대씩) | 정답률 | 아는 고장 감지 | 처음 보는 고장 감지 | 오경보 | 원인 맞음 |
|---|---|---|---|---|---|
| 아는 고장만 | **99.2%** | **99.2%** (128/129) | – | **0.8%** | **96.9%** |
| 고장 절반이 처음 보는 고장 (기본 세기) | **98.0%** | 100% (58/58) | **97.2%** (70/72) | **2.5%** | **96.1%** |
| 충분히 진행된 고장 (세기 1.2~1.5배) | 98.0% | 100% (70/70) | 100% (54/54) | 4.0% | 96.0% |
| 세기 무작위 0.4~1.0배 (현실 조건) | 94.0% | 92.9% | 97.1% | 7.2% | 96.2% |

- **네 지표가 모두 95~99%인 조건:** 아는 고장만(정답률 · 아는 고장 · 원인 + 오경보 0.8%), 기본 세기(정답률 98.0 · 처음 보는 고장 97.2 · 원인 96.1, 아는 고장은 58대 모두 잡아 100%)
- 100%는 그 조건의 해당 로봇을 모두 잡은 값 (예: 58대 중 58대). 대수가 적을수록 우연이 섞이므로 '98~100% 범위'로 읽는 게 맞음
- 현실 조건(세기 무작위)에서는 약한 고장을 놓치고 오경보가 7.2%로 높아짐 → 약한 아는 고장 감지 · 오경보가 남은 과제
- 남은 원인 오류: 기어 마모를 '마찰 증가'로 보는 경우 (250대 중 4대)
- 원인 맞음: 아는 고장은 종류, 처음 보는 고장은 '처음 보는 이상'(베어링은 '마찰 증가'도)이면 맞음으로 셈
