# 실측 고장 기록 방법과 실제 성능 확인 (11/20)

지금 가진 실측 고장은 **앞 오른쪽 바퀴 테이프 20초짜리 파일**뿐이라, 모델이 실제 로봇에서 고장을 언제 잡는지 확인하지 못했습니다.
모델은 **로봇마다 처음 5분을 '평소'로 삼고, 1분마다 판정**하므로 아래처럼 **한 파일을 끊지 않고** 길게 기록해야 합니다.

## 1. 기록 순서 (한 번 = CSV 한 파일, 끊지 않기)

| 구간 | 시간 | 할 일 |
|---|---|---|
| ① 정상 | **6분 이상** | 평소처럼 주행 (같은 바닥 · 같은 속도 단계, 가능하면 속도 5와 7을 섞어서) |
| ② 고장 내기 | 30초 안쪽 | 기록은 켜 둔 채 로봇을 세우고 고장을 냄 (테이프 감기 · 나사 풀기 등). **이 시각(분:초)을 메모** |
| ③ 고장 | **3분 이상** (5분이면 더 좋음) | ①과 같은 바닥 · 같은 속도로 다시 주행 |

- 고장 종류 예: 테이프 감기(바퀴 불균형 · `unbalance`), 바퀴 · 모터 나사 반 바퀴 풀기(체결 풀림 · `looseness`), 바퀴 축에 천 · 고무줄 감아 뻑뻑하게(마찰 증가 · `bearing`)
- **정상만 10분 이상** 기록한 파일도 2~3개 만들기 (오경보 확인용, 바닥을 바꿔 가며)
- 엔코더는 4개 모두 기록하면 가장 좋음 (gz 회전 속도 · 바퀴 비교 특징). enc2 하나만 있어도 진단은 됨
- 기록 스케치의 MPU6050 샘플링(약 480 Hz) · 범위(±4 g)는 지금과 같게

## 2. 라벨 붙이기 (선택: 성능 숫자를 낼 때만)

```
python 실행/라벨_붙이기.py --file data/실측_고장/run01.csv --start 6:10 --kind unbalance --wheel fr
```
→ `run01_label.csv`가 생김 (고장 시작 전 = 정상, 이후 = 고장). 진단만 볼 때는 라벨이 없어도 됨

## 3. 진단해서 확인하기

가상 시험으로 학습한 모델로 바로 진단 (`가상테스트/성능시험.py`를 한 번 돌리면 모델 파일이 생김):
```
python run.py diagnose --path data/실측_고장 --model 가상테스트_결과/성능시험/model_bundle.joblib
```
- 결과: `reports/diagnose/파일이름.csv`(1분마다 상태 · 원인 · 근거) + 점수 그래프 `.png`
- 확인할 것
  - 정상 구간(5분 뒤 ~ 고장 내기 전)에 **'주의'가 뜨지 않는가** (오경보)
  - 고장을 낸 뒤 **몇 분 만에 '주의'가 뜨는가** (감지 시간)
  - 추정 원인이 낸 고장과 맞는가 (테이프 → '앞 오른쪽 바퀴 불균형')
- 정상만 기록한 파일에서 끝까지 '정상'인지도 확인

## 4. 실측 기록이 여러 개 모이면

실측 기록을 학습에도 넣어 다시 학습: `data/`에 넣고 `python run.py train` → `python run.py diagnose`.
처음 보는 로봇으로 재야 하므로, 시험에 쓸 기록은 학습 폴더에 넣지 말 것.
