# 내 데이터 넣는 법

CSV를 `user_data` 폴더에 넣고 실행합니다. 대시보드에서 파일을 올려도 됩니다.

```bash
python run_custom.py check
python run_custom.py train
python run_custom.py diagnose
```

- `check`: 형식을 검사하고 고칠 점을 알려 줍니다.
- `train`: 내 데이터로 모델을 학습합니다 (`artifacts/user_model.joblib`). 건너뛰면 시뮬레이션으로 학습한 모델을 씁니다.
- `diagnose`: 로봇별로 회차별 점수·상태·원인을 `reports/user/`에 CSV와 그래프로 저장합니다.

대시보드는 `streamlit run dashboard/app.py`로 열고 **입력 데이터 → 내 데이터**를 고릅니다.

실제 파일이 아직 없으면 `python run_custom.py sample`로 예시 파일을 만들어 흐름을 먼저 확인할 수 있습니다. 예시는 시뮬레이터로 만든 것이니, 실제 데이터를 넣을 때 `sample_`로 시작하는 파일을 지우세요.

## 파일 형식

**한 줄이 진동 샘플 하나**이고, 파일 하나가 로봇 1대입니다. `.csv`, `.csv.gz`, 파일이 하나 든 `.zip`을 읽습니다.

```csv
time,lap,segment,speed,left_vib,right_vib,left_cur,right_cur,left_temp,right_temp
0.000,0,복도A,1.02,0.0132,-0.0071,0.84,0.81,31.2,30.9
0.001,0,복도A,1.02,0.0094,0.0023,,,,
0.002,0,복도A,1.02,-0.0051,0.0110,,,,
```

전류·온도처럼 느린 센서는 값이 있는 줄에만 채우면 됩니다. 1초 창마다 평균을 내고, 값이 없는 창은 직전 값을 씁니다.

### 필수 열

| 열 | 단위 | 설명 |
|---|---|---|
| `left_vib` 또는 `right_vib` | g | 바퀴·모터의 진동. 둘 다 있어야 좌우 비교와 바퀴 위치 판단을 합니다 |
| `time` | 초 | 숫자 또는 날짜·시각. 샘플링 주파수를 여기서 계산합니다. 없으면 대시보드의 값이나 `--fs`를 씁니다 |

### 있으면 좋은 열

| 열 | 단위 | 없을 때 |
|---|---|---|
| `left_cur`, `right_cur` | A | 전류 특징이 0이 되어 부하가 늘어나는 고장을 놓칠 수 있음 |
| `left_temp`, `right_temp` | °C | 온도 특징이 0이 됨 |
| `speed` | m/s | 1 m/s로 가정. 회전 주파수(1X) 특징과 전류 잔차의 의미가 약해짐 |
| `lap` | 정수 | 60초를 1회차로 나눔 (`--lap-s`로 변경). 회차는 점수를 묶고 남은 시간을 세는 단위입니다 |
| `segment` | 글자 | 전체를 한 구간으로 봄. 구간별 기준(복도 지문)을 쓰지 못해 노면 차이가 걸러지지 않음 |
| `bump` | 0/1 | 문턱 통과 순간을 판정에서 빼지 못함 |
| `robot` | 글자 | 파일 이름을 로봇 이름으로 씀. 값이 있으면 한 파일을 여러 로봇으로 나누고, 여러 파일을 한 로봇으로 이어 붙임 (파일 이름 순서) |

열 이름이 다르면 머리글을 고치거나 `config.py`의 `COLUMN_ALIASES`에 추가하세요. 바퀴 반지름이 8 cm가 아니면 `config.py`의 `ROBOT["wheel_radius"]`도 바꿔야 합니다.

### 라벨 열 (학습용)

| 열 | 값 |
|---|---|
| `fault_kind` | `normal`, `bearing`, `looseness`, `unbalance`, 또는 직접 정한 이름 |
| `fault_wheel` | `left`, `right` |
| `fault_severity` | 0~1. 0.8 부근을 건강 점수 9(정지 위험)로 맞춥니다 |

## 꼭 지켜야 할 것

1. **로봇마다 처음 5회차는 정상이어야 합니다.** 이 구간으로 그 로봇의 기준을 만들기 때문입니다. 고장 난 상태부터 시작하는 기록은 정상 기록 파일과 `robot` 값을 같게 맞춰 이어 붙이세요. 파일 이름 순서대로 붙으니 정상 파일 이름이 앞에 오게 하세요.
2. **진단하려면 6회차 이상**, **학습하려면 처음 5회차를 뺀 정상 구간이 100초 이상** 필요합니다.
3. **이상 감지 학습에는 고장 없는 기록이 필요합니다.** 라벨이 없으면 모든 데이터를 정상으로 보고 학습하므로, 고장 기록을 라벨 없이 섞으면 고장을 정상으로 배웁니다.
4. **성능은 학습에 쓰지 않은 로봇으로 확인하세요.** `python run_custom.py train --holdout R3,R4`로 뺄 수 있고, 같은 베어링·같은 로봇의 기록이 학습과 평가에 나뉘어 들어가면 성능이 부풀려집니다.

## 넣는 데이터에 따라 나오는 결과

| 데이터 | 이상 감지 | 건강 점수 | 원인 분류 | 남은 회차 |
|---|---|---|---|---|
| 시뮬레이션 모델로 진단만 | 참고용 | 시뮬레이션 눈금 | 시뮬레이션 패턴 기준, 참고용 | 참고용 |
| 정상 기록으로 학습 | 가능 | 3점까지만 의미 있음 (점수가 9를 크게 넘을 수 있음) | 없음 | 예측 안 함 |
| 고장 종류 라벨까지 학습 | 가능 | 고장 창 중앙값 = 9 | 가능 | 눈금 정확도에 따름 |
| 고장 정도까지 학습 | 가능 | 고장 정도 0.8 = 9 | 가능 | 진행형 기록일수록 믿을 만함 |

칼만 필터 잡음 값은 시뮬레이션으로 맞춘 값이라, 실제 데이터에서는 90% 범위를 다시 확인해야 합니다.
